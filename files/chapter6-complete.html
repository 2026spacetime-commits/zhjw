🤔 一个值得思考的问题：为什么还需要 Pandas？

⚖️

list 能存数据，dict 能查数据，NumPy 能算数据 —— 但我们仍然"缺"一个东西

Lists hold data, dicts look up data, NumPy computes data — what's still missing?
数据有"名字"吗？：一个 Python 列表只是位置的集合——我们要靠下标 lst[0] 找数据，但现实中的数据是有意义的：这一列是"姓名"，那一列是"成绩"。给数据起名字、按名字取数据，才是表格的本质。
数据是"混杂"的：现实中一张成绩单，既有姓名（字符串）、又有分数（整数/浮点）、还有是否及格（布尔）。而 NumPy 数组要求类型统一——一旦设定 int 或 float 就"从一而终、不得改变"。这太"纯洁"了，没法直接描述真实世界。
数据要"会读会画"：分析的第一步是读取 CSV、Excel 等外部文件，最后一步是画图展示。这些能力，list/dict 没有，NumPy 也没有——它们需要 Pandas 来补齐。
💡 关键洞察：NumPy 解决的是"高性能数值计算"，Pandas 解决的是"带标签、混杂类型的表格数据分析"。二者不是替代关系，而是接力关系——Pandas 底层就构建在 NumPy 之上。

§0.1 · 认识 Pandas

Pandas 是什么？—— 数据分析界的"瑞士军刀"

出身：Pandas 是 Python 生态环境下非常重要的数据分析包，它是一个开源的、基于 BSD 开源协议的库。正因为有它的存在，基于 Python 的数据分析才能大放异彩。
与 NumPy 的关系：Pandas 吸纳了 NumPy 中的很多精华，却在数据分析方面"青出于蓝而胜于蓝"。Pandas 在设计之初就倾向于支持图表和混杂数据运算；相比之下 NumPy 显得"纯洁"很多——数组一旦设定类型就不得改变。
更高级的数据结构：Pandas 是基于 NumPy 构建的，但它含有比 ndarray 更高级的数据结构和操作工具，如 Series 类型、DataFrame 类型等。有了这些高级数据的辅佐，数据分析变得更加便捷与高效。
三大能力：①通过管理索引快速访问、执行分析和转换运算；②高效绘图（用 Matplotlib 作为后端）；③数据读取"小能手"——支持从 CSV、TXT、Excel、HDF5 等文件读取数据。
一句话总结：NumPy 提供"高性能的数组"，Pandas 提供"会讲人话的表格"。本课程的后续章节将在这张"表格"上完成数据读取、清洗、分析与可视化。

§0.2 · 数据结构总览

Pandas 的三种数据结构：一维 / 二维 / 三维

Pandas 的使用便捷，离不开高效的底层数据结构的支持。它主要有三种数据结构：

📏
Series一维 · 本章重点
类似于一维数组。一组数据 + 与之对应的标签（索引）。可以理解为 Excel 表中的"一列"，自带左侧编号。是理解 DataFrame 的基础。
🗂️
DataFrame二维 · 本章重点
类似于二维数组，即"表格"。可以理解为 Excel 中的"一张表"，既有行索引（最左编号）又有列索引（列名）。可由多个 Series 组合而成。
📌 Panel（三维数组）：由于并不常用，新版本的 Pandas 已经将其列为过时（Deprecated）的数据结构。本章只介绍前两种数据结构的用法。
记忆线索：Series 是"一维 + 标签"，DataFrame 是"二维 + 行列标签"。维度升一级，分析能力就上一个台阶——先学好 Series，DataFrame 就是多个 Series 的"集合体"。

§0.4 · Series 初识

Series 是什么？—— 一种"自带标签"的一维数组

📏

Series = 一组数据 + 一组对应的标签（索引）

one-dimensional labeled array — a 1D array with a label for every element
import pandas as pd 
s = pd.Series([1, 2, 3, 4, 5]) 
print(s)  
0 1 
1 2
2 3 
3 4 
4 5
dtype: int64
创建语法非常简单：pd.Series(data, index = index)。其中 data 就是数据源，其类型可以是一系列的整数、字符串，也可是浮点数或某类 Python 对象。
默认索引：默认索引就是数据的标签（label）。注意观察输出——索引在左，数值在右，这是 Series 的经典视图。
本质：Series 是一种自带标签的一维数组（one-dimensional labeled array）。可以通过 s.index 和 s.values 两个属性，分别获取索引和数组元素值。

§0.4 · 创建方式(1)

创建 Series：用列表填充数据源

s = pd.Series([1, 2, 3, 4, 5]) # 数据源是列表 
print(s)
Series 与列表的相似：Series 的数据源可以用列表来填充。二者有相似之处——它们内部都包括一系列的数据。
根本不同：元素类型：列表内的元素可以是相同类型的，也可以是不同类型的（1, 'a', 3.14 混在一起没问题）。而 Series 则不同，它依赖于 NumPy 中的 N 维数组（ndarray）而构建，因此其内部的数据要整齐划一，数据类型必须相同。
自动索引：此外，Series 增加对应的标签（label）作为索引。如果没有显式添加索引，Python 会自动添加一个 0~n-1 内的索引值（n 为 Series 对象内含元素的个数）。通常的视图是索引在左，数值在右。
一句话对比：列表是"自由散漫"的容器，想放什么放什么；Series 是"军事化管理"的一维数组，所有人必须同一类型——这是它高性能的代价，也是它强大的基础。

创建 Series：显式指定索引，索引可以是任何类型

# 用 index 参数显式指定索引（不再必须是 0~n-1）

标签类型自由：在创建 Series 对象时，其标签并不必然是 0~n-1 内的数字，它也可以被显式指定为其他类型——字符串、日期、元组都可以。

§0.4 · 创建方式(3)

创建 Series：由 Python 字典"打包"而来

Series 与字典颇有相似之处：Series 中的 index 可对应字典中的 key，Series 中的 value 与字典中的 value 相同。因此，Series 也可以由现有的字典数据类型通过"打包"来创建。
# 用字典创建 Series：dict 的 key 自动成为 Series 的 index 
s = pd.Series({'张三': 78, '李四': 92, '王五': 85}) 
print(s)
张三 78 
李四 92 
王五 85 
dtype: int64
✏️ 注意：由于字典中的 key 可以"对标"Series 中的 index，所以用字典创建时，无须单独设置 Series 所需的 index 参数——dict 的 key 自动填充了索引。
总结：dict 是"无序的键值对"，Series 是"有序的带标签数组"。从 dict 到 Series，只是"换了个更有组织性的身份"。

§1.1 · 数据访问

访问 Series 中的数据（1）：像 NumPy 一样用下标

核心思路：一旦指定 Series 的索引，就可以通过特定索引值，访问、修改索引位置对应的数值。我们知道，Series 对象在本质上就是一个带有标签的 NumPy 数组，因此，NumPy 中的一些概念和操作手法，可直接用于 Series 对象。
首先：像 NumPy 数组一样，可通过下标存取 Series 对象内部的元素。
s = pd.Series([78, 92, 85, 63]) 
print(s[0]) # 下标 0 → 第一个元素 78 
print(s[2]) # 下标 2 → 第三个元素 85 
s[1] = 99 # 通过下标修改元素 
print(s)
78 
85 
0 78 
1 99 ← 被修改 
2 85 
3 63 
dtype: int64
为什么能这样用？：因为 Series 底层就是 ndarray。上一章学的下标、切片、布尔索引这些"肌肉记忆"，在 Series 上几乎全部直接生效。

访问 Series 中的数据（2）：用标签"指名道姓"

标签访问：Series 对象号称"带有标签的数组"，所以它的标签（即特定索引）也可以用来访问、修改特定位置数据。这比下标更有意义——我们按"名字"取数，而不是按"位置"。
s = pd.Series([78, 92, 85, 63], index=['张三', '李四', '王五', '赵六']) 
print(s['张三']) # 用标签 '张三' 取数 → 78

78 
张三 78 
李四 92 
王五 60 ← 被修改 
赵六 63 
dtype: int64
💡 体验差异：用标签访问就像在通讯录里"搜名字"，用下标访问就像"翻到第几页"。标签让代码可读、可维护、贴近语义——这就是 Pandas 相对 NumPy 的升华之处。

§1.2 · 布尔索引

布尔索引：用"是/否"筛选出想要的数据

核心逻辑：类似于 NumPy，Series 也支持利用布尔表达式提取符合条件的数值。代码的逻辑判断会产生一个与 Series 对象维度相同的布尔矩阵，而这个布尔矩阵本身又可以作为 Series 对象的下标，用于获取值为 True 的位置对应的数值，从而达到抽取特定样本的目的。
##
apts = pd.Series([80, 95, 70, 88, 65]) 
print(apts > apts.median()) # 逻辑判断 → 布尔 Series 
print(apts[apts > apts.median()]) # 布尔 Series 作下标 → 只取 True 的值
0 False 
1 True 
2 False 
3 True 
4 False 
dtype: bool 

1 95 
3 88 
dtype: int64
理解"索引操作"：这是一个索引操作，它会从 apts 中选择那些满足 apts > apts.median() 条件的元素。只有在布尔表达式中对应位置为 True 的元素才会被选中。

§1.2 · NumPy 协同

Series 作为 NumPy 函数的参数：无缝协作

本质：Series 就是"一系列"的数据，类似数组向量。它可以在 NumPy 函数的操作下，达到向量操作的目的，而不用像 C 或 Java 等编程语言一样使用 for 循环来完成类似的操作。
写法：直接把 Series 对象塞进 NumPy 函数当参数，函数对每个元素逐一作用，返回结果仍是带索引的 Series。
import numpy as np 
s = pd.Series([1, 4, 9, 16])
print(np.sqrt(s)) # 开平方：1, 2, 3, 4 
print(np.exp(s)) # 指数运算

dtype: float64

dtype: float64
🎯 为什么说这是"省事"的？：C/Java 要写 for 循环逐元素处理，Python 原生的 map 也要包一层。而 Pandas + NumPy 的组合拳，让一个数学公式级别的表达式就完成整个向量操作——代码即数学。

§1.3 · 切片操作

⚠️ 重点：数字切片"左闭右开"，标签切片"左闭右闭"

类似于 NumPy，可以通过索引切片选取或处理 Series 中的一个或多个值，其返回的结果依然是 Series 类型的对象。但两种切片的区间规则截然不同：

切片方式 区间规则 示例 取到的元素
数字切片 左闭右开 [start, end)：包含起点，不含终点 s[1:3] 第 1、第 2 个元素；第 3 个取不到
标签切片 左闭右闭 [start, end]：包含起止两端 s['a':'c'] 'a'、'b'、'c' 三个元素全部取到
s = pd.Series([10, 20, 30, 40], index=['a', 'b', 'c', 'd']) 
print(s[1:3]) # 数字切片 → 左闭右开：b, c 
print(s['a':'c']) # 标签切片 → 左闭右闭：a, b, c
✏️ 记忆口诀：「标签切片闭右闭，数字切片开右开」。这是面试和作业中最常考的一个点——同样是切片，两种写法的终点处理完全不同。

§3.3 · loc / iloc

iloc 方法：基于位置的行列访问（DataFrame 版切片）

iloc 则完全是基于位置的索引：其中的参数都是数字（该方法开头的 "i" 是指 index，特指数字索引）。iloc 的用法与 NumPy 的切片用法完全一样，可以把它视作 DataFrame 版本的切片操作。

§4.2 · 轴方向总结

轴方向总结：删除 vs 统计，两个视角一张表

操作场景 axis=0（垂直 · index） axis=1（水平 · columns）
删除操作 drop(行名, axis=0) → 删行 drop(列名, axis=1) → 删列
添加操作 loc[新行索引]=值 → 加行 df['新列']=values → 加列
统计运算 df.sum(axis=0) → 沿垂直方向求和，得到每列的和 df.max(axis=1) → 沿水平方向求最大，得到每行的最大值
别名 axis='index' axis='columns'
✏️ 记忆口诀：「axis=0 跨行垂直，axis=1 跨列水平」——0 像一竖（|），1 像一横（—）。删除时沿哪个方向"切一刀"，统计时沿哪个方向"压扁求和"。
易错提醒：删除时 axis=0 删行；但统计时 sum(axis=0) 得到的是"每列的和"。不要用"删行/删列"反推统计方向，用"箭头方向"来想：箭头指向谁，谁就是操作对象。
